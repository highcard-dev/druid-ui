# Druid UI 4.0.0-rc.1

This is a breaking v4 release candidate, published on npm's `next` channel.
Existing packages' `latest` tags remain on 3.1.0. Stable v4 promotion is separate.

## Try the Rust-first starter

Install Node.js 24+ and stable Rust/Cargo, then run:

```sh
rustup target add wasm32-unknown-unknown
npx create-druid-ui@next my-druid-ui
cd my-druid-ui
npm run dev
```

Use a browser with WebAssembly JSPI (`WebAssembly.Suspending` and
`WebAssembly.promising`). Unsupported engines display an explicit error;
there is no synchronous fallback.

To opt an existing project into the new SDK explicitly:

```sh
npm install @druid-ui/host@next @druid-ui/client@next
npm install --save-dev @druid-ui/build@next
```

## Breaking changes

- Authored `.openui` documents and a reusable React host replace the legacy
  JSX/DOM rendering pipeline. Existing applications require explicit migration.
- Four packages remain: `@druid-ui/host`, `@druid-ui/client`, `@druid-ui/build`
  (including `/vite`), and `create-druid-ui`.
- The old component, platform and standalone Vite packages are retired from this
  SDK. Their existing published versions remain available and unchanged.
- Raw JavaScript execution, the old DOM WIT, callback/node registries and copied
  framework-specific WIT are removed.
- Native async WIT supports initialization, named actions and directly awaited
  host tools. The manual request-ID/completion protocol is removed.
- Rust is preferred for guest behavior and all scaffolder templates. React hosts
  remain TypeScript. Optional TypeScript guests use QuickJS rather than
  ComponentizeJS/StarlingMonkey.
- The shared build tool handles Cargo, canonical/custom WIT, watch/reload and
  successful artifact replacement. Retain each Rust guest's Cargo.lock.

Host applications explicitly register tools and own authentication, deployment
scope, path validation and confirmation policies. Instance cancellation and
stale-state protection remain supported.

## Verification

Release preparation includes SDK tests, real Rust/WASM integration, all example
builds, packed-template builds and browser verification. After publication, a
fresh Rust starter must install and build against the actual npm packages.

This release does not migrate consumer applications, change backends, or deploy
production services.
